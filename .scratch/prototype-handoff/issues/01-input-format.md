# 01 輸入格式：自由文字 vs 欄位模板 vs 混合

Type: grilling
Status: resolved
Blocked by:

## Question

PM 描述 prototype 的輸入該長什麼樣？自由文字/口述最彈性，但欄位模板較不易出錯（PM 已表達這個張力）。要決定：純自由文字、有欄位模板、還是「自由文字 + 可選模板」的混合？若採模板，欄位有哪些（頁面/區塊/元件/互動…）？

## Answer

**採 B：自由文字輸入 + AI 回述確認**，不用 PM 填表。

- **輸入**：PM 用自由文字/口述隨意描述，無強制模板。
- **收斂機制**：AI 解析後回述一份**結構化摘要**給 PM 確認/更正，摘要只含 PM 能判斷的兩類：
  1. **解讀到的元件**（對到 Pi DS 實際 class，如「選單」→ 確認是 `dropdown` 還是原生 `select`）
  2. **版面/排列關係**（誰在誰上下、幾欄）
- **PM 責任邊界**：PM 只負責確認元件 + 版面。**狀態（error/disabled/送出後）與資料/行為（選項來源、送去哪）PM 不懂，不問 PM**，AI 直接在產物標「待前後端補」。
- **回合**：確認可多輪，直到 PM 點頭；元件/版面歧義在此收斂。

理由：PM 只可靠掌握「元件選擇 + 版面」兩類；模板一放技術欄位 PM 就卡且仍會猜，回述確認把歧義丟回一個 PM 答得出的是非題。

**下游耦合**：回述摘要的「元件 + 版面」結構，與 `02 Handoff 規格格式` 的輸出欄位高度重疊 —— 兩者的共用結構在 `02` 一起定。
