# 會員列表工具列（日期範圍 + 匯出）— 後端 Handoff

## 資料契約

Fixture 檔就是契約 —— controller 傳出同樣結構即可，前端 blade 不用改：

| Fixture | 對應變數 | 結構 |
|---------|---------|------|
| `prototypes/project-a/fixtures/member-list-toolbar.php` | `$toolbar` | `['dateFrom' => string, 'dateTo' => string]` |

空字串＝未選。這是**表單預填值**，用途是讓使用者送出後回到頁面時保留已選的範圍。

## 型別待補

| 欄位 | 目前 fixture 值 | 實際型別 |
|------|----------------|---------|
| `dateFrom` | `''` | `<input type="date">` 送出的是 `YYYY-MM-DD` 字串。要轉 Carbon 還是原樣進 query？— 🔧 待補 |
| `dateTo` | `''` | 同上。**注意邊界**：`dateTo` 通常要含當日整天（`<= dateTo 23:59:59`），只用 `<= dateTo` 會漏掉當天的資料 — ⚠️ 待確認 |

## 選項 / 資料來源

日期沒有選項清單（原生 date input）。但有兩個範圍問題：

- **可選範圍下限**：資料庫最早的會員加入日？還是不限？— 🔧 待補
- **可選範圍上限**：今天？允許選未來日期嗎？— 🔧 待補
- **預設值**：進頁面時是空的（目前 fixture），還是預設「最近 30 天」？— ⚠️ 待確認（會影響首次進頁的查詢量）

## 送出目標 / API 意圖

**這一列有兩個不同的送出行為**，前端 prototype 沒有區分，需要後端定義：

| 動作 | 意圖 | 待確認 |
|------|------|--------|
| 日期改變 | 篩選會員列表 | 是併進既有的篩選查詢（同一個 GET，多兩個 query param），還是獨立 endpoint？— ⚠️ 待確認 |
| 按「匯出」 | 匯出查詢結果 | endpoint / method？— ⚠️ 待確認 |

匯出的細節全部待定：

- **匯出格式**：CSV / Excel / 兩者可選？— 🔧 待補
- **匯出範圍**：當前篩選條件的結果，還是全部會員？（含 `member-list.filters` 的關鍵字與狀態）— ⚠️ 待確認
- **匯出欄位**：表格顯示的四欄（姓名 / Email / 狀態 / 加入日期），還是更多？— 🔧 待補
- **同步或非同步**：直接回檔案下載，還是丟背景任務 + 完成通知？資料量大時前者會逾時 — ⚠️ 待確認（**這題會反過來決定前端要不要做 loading 狀態**）
- **權限**：誰可以匯出？匯出行為要不要寫 audit log？（會員 Email 是個資）— ⚠️ 待確認

## 驗證規則

| 欄位 | 規則 |
|------|------|
| `dateFrom` | 選填、`Y-m-d` 格式 — 🔧 待補 |
| `dateTo` | 選填、`Y-m-d` 格式、**不得早於 `dateFrom`** — 🔧 待補 |
| 範圍跨度 | 是否限制最大跨度（例如一年）以免匯出過大？— 🔧 待補 |

驗證失敗的回饋位置前端已預留：`<x-pi::form-control state="invalid" feedback="訊息">`。
